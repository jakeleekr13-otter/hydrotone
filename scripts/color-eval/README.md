# Colour evaluation harness

This harness measures the colour algorithm on still images. It compiles the app's own Processing sources into a Mac command-line tool. So it measures the shipping code, not a copy.

## What it renders

For each image the tool renders these variants:

| Variant | Meaning |
|---|---|
| `original` | The source, no correction |
| `grayworld` | A simple gray-world white balance, as a floor to beat |
| `current` | `FilterEngine.apply` only (the fallback path) |
| `restoration` | The physical restoration only, blended by plan confidence |
| `combined` | `RestorationEngine.combined`, the shipping output for photo, batch and video |
| `uniform` | `combined` with one constant (median) depth. It stands in for the video path |
| `reference` | The target image, when the data set has one |

## Metrics

All metrics come from the rendered 8-bit sRGB image.

- **deltaE**: mean CIE76 colour difference to the reference. Lower is closer.
- **PSNR**: over RGB, against the reference.
- **SSIM**: on L*, 8x8 box windows, stride 4.
- **meanL**: mean L*. This is overall brightness.
- **localContrast**: mean L* standard deviation in 16x16 windows. A water veil lowers it, so it works as a haze measure that does not depend on hue.
- **farLocalContrast**: the same, but only in the far 30% of the depth map (mostly water).
- **farHue / farChroma**: the CIELAB hue angle and chroma of the far region's mean colour.
- **farHueOK / farChromaOK**: the same in OKLab.
- **nearRG**: the red / green ratio in the near 30% of the depth map (mostly the subject).
- **contrastL**: global L* standard deviation.

### Why OKLab for water hue

- CIELAB hue cannot tell blue colours apart. Azure is 273°, pure sRGB blue is 306° and violet is 310°.
- OKLab separates them. Cyan is 208°, azure 249°, pure blue 264°, indigo 276° and violet 292°.
- Water hue bands therefore use OKLab whenever the CSV has the OK columns:

| Band | OKLab hue |
|---|---|
| neutral | chroma below 0.02 |
| green | below 180 |
| cyan | 180 to 235 |
| blue | 235 to 270 |
| indigo | 270 to 282 |
| violet | 282 and above |

- The JSON key `violet(>=265)` is kept for compatibility. With OK columns it means OKLab 282 and above.

## Data sets

None of the data is in git.

| Set | Location | Notes |
|---|---|---|
| UIEB (890 pairs + 60 challenging) | `DeveloperMedia/samples/photo/` | Download it from the UIEB authors; it is not redistributed. Its references are human-picked outputs of older methods, not ground truth. Use them as a guide. |
| Market before/after pairs (m1-m4) | `DeveloperMedia/market/{raw,ref}/` | Private. They were cut from web images the product owner shared. |
| Real photos (r01-r15) | listed in `real_set.txt`, relative to `DeveloperMedia/` | The product owner's own dive photos. No reference exists. r14 and r15 are the green or teal examples. |
| Neutral ramp | generated by `make_neutral_ramp.py` | A correct pipeline keeps it colourless. |

- All developer media lives in `DeveloperMedia/` at the repo root. It is git-ignored and outside every Xcode target.
- Never put media under `HydroToneTests/`. That folder is a synchronized Xcode group, so git-ignored files there are still copied into the test bundle.
- Same-named files in two folders break `build-for-testing`.

### UIEB splits

- The sorted UIEB list is split by index: odd indices are `dev`, even indices are `holdout`.
- `dev:N` is the 12 visual-set images (`visual_names.txt`) plus the first N dev images.
- `holdout:N` is the first N holdout images.
- Tune on dev. Check holdout only once, at the end.

## How to run

```sh
# Tuning scorecard on the current working-tree sources:
scripts/color-eval/tune_eval.sh my-run
# The same on another source folder, for example a copy of git HEAD:
HT_EVAL_SOURCES=/path/to/Processing scripts/color-eval/tune_eval.sh head-run
# One UIEB split (default dev:28):
scripts/color-eval/run_eval.sh dev-run holdout:40
```

Environment variables:

| Variable | Default |
|---|---|
| `HT_EVAL_SOURCES` | `HydroTone/Processing` |
| `HT_EVAL_DATA` | `DeveloperMedia` |
| `HT_EVAL_MARKET` | `DeveloperMedia/market` |
| `HT_EVAL_OUT` | `$TMPDIR/hydrotone-color-eval` |

- Results never go into the repo.
- The first run compiles the Core ML depth model into the cache.

`tune_eval.sh` prints `report.txt` and writes three sheets: `market_sheet.jpg`, `bmw_sheet.jpg` and `real_sheet.jpg`. Open the sheets and judge them by eye. The numbers do not show everything.

## Guards used for tuning

A change is accepted only if all of these hold:

- The neutral ramp's max Lab chroma is 3 or less, on both `combined` and `uniform`.
- Dev (40 images): deltaE and `uniform` deltaE are not worse than the committed code by more than 0.5.
- Dev: indigo + violet water count (OKLab) does not grow. Green water left is at most 2 of 6.
- The UIEB best images (576, 433) are not worse by more than 1 deltaE.
- Real photos: no image ends in indigo or violet (OKLab 270 or more) unless its original was already there. r04's anemone is really magenta.
- Keep what the market pairs gained so far.
